# Security Policy

## Status

Faithful Ferret is in the design phase. **It is not ready for use**, and there is no released code to attack yet.
Please do not store real passwords in anything built from this repository until a release says it is ready.

## Reporting a vulnerability

**Do not open a public issue for security problems.**

Once it is enabled, report it privately through GitHub's
[private vulnerability reporting](https://github.com/Ferdinand99/Faithful-Ferret/security/advisories/new): go to
the repository's **Security** tab and click **Report a vulnerability**. Only you and the maintainer can see the
report. Until it is enabled, contact the maintainer through their
[GitHub profile](https://github.com/Ferdinand99) and ask for a private channel before sharing details.

Please include what the issue is and where, how to reproduce it, and the impact you think it has.

At this stage, flaws in the published design (the threat model and the cryptographic design, once they exist) are
as welcome as flaws in code.

## No external audit

Faithful Ferret has not been independently audited and no external audit is funded. Security work is done in the
open and reviewed internally; see the security approach in the [README](README.md#security-approach).
