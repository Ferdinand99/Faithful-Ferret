# Operations register

Every vector case names an `op`. This register maps each `op` to the Rust
function that runs it, the WASM method that exposes it, and the shape of the
case's `input`. The Rust, Node and browser runners are table-driven from this
list. A case may only use an `op` that is listed here.

Rows are added by the task that introduces the operation. The first column
holds the op name in backticks.

Mutation proof ops: `unlock-method.add`, `unlock-method.remove`, `unlock-method.password.put`, `unlock-method.recovery.put`, `recover` (label `ferret/v1/recovery-req`, signed by `sk_r`) and `rekey`.

Generated checkpoint rows (`"generate": { "count": n }`): row `i` (0 <= i < n), in index order and not sorted, has `item_id` = the first 16 bytes of `SHA-256("ferret/checkpoint-vector/id" ‖ u32be(i))`, `rev = 1 + i mod 7`, and `h = SHA-256("ferret/checkpoint-vector/hash" ‖ u32be(i))`, or a tombstone (`h` = 32 zero bytes) when `i mod 5 = 0`.

Text input is either `{ "utf8": hex }` (bytes, used for input that is not UTF-8) or `{ "segments": [ { "escapes": "U+0061 U+030A", "repeat": 12 } ] }`: the text is the concatenation of the segments, each segment being its code points repeated `repeat` times. A short text may also carry `"text"` for reading; it must equal the segments.

Byte segments are `{ "segments": [ ... ] }`: the bytes are the concatenation of the segments. A segment is `{ "hex": hex, "repeat": number }` (the bytes repeated), so a body of 61 439 bytes is a few lines, or `{ "keys": { "count": number, "value_hex": hex } }`: `count` map entries, each the five-digit counter as a CBOR text ("00000", "00001", ...) followed by the bytes `value_hex`, with no map head.
